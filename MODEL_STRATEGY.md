# Estrategia de trabajo entre modelos

“Astra” y “Luna” son nombres de roles del flujo de este proyecto; no garantizan disponibilidad o capacidades de un modelo concreto en una instalación.

## Análisis y revisión — Astra

Revisar contexto, simplificar alcance, diseñar UX, contrastar alternativas y registrar propuestas. En fase 0 entrega documentación y se detiene para revisión. No implementa automáticamente después de especificar.

## Implementación incremental — Luna

Recibe una fase aprobada, lee requisitos/decisiones, verifica documentación actual de dependencias y completa código, pruebas, interfaz y documentación correspondientes. No interpreta una propuesta como aceptación ni amplía alcance por su cuenta.

## Traspaso obligatorio

- Fuente de verdad: AGENTS para trabajo; decisiones aceptadas, alcance y requisitos para producto.
- Estado de entrada: fase autorizada y progreso real de `docs/14`.
- Entregable: criterios de `docs/12`, pruebas con resultados reales y documentos actualizados.
- Condición de parada: cerrar fase encargada y reportar límites; no comenzar siguiente bloque automáticamente.
- Si falta una decisión que afecta arquitectura o alcance, preparar alternativa concreta y solicitar revisión antes de implementarla.

La elección de modelo no cambia requisitos ni constituye autorización. No se afirma que documentación redactada esté implementada o validada por estudiantes.
